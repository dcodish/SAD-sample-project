## מיפוי בעיות → החלטות עיצוב

טבלה זו מציגה כיצד כל בעיה עסקית מתורגמת להחלטת עיצוב במערכת. זה הגשר בין האנליזה לפיתוח.

| בעיה | החלטת עיצוב | היכן ממומשת |
|---|---|---|
| P-01 — יצירת הזמנה איטית | טפסים ייעודיים נפרדים: `CreateDeliveryOrderPanel` ו-`CreatePickupOrderPanel` עם שדות קבועים ואימות | `DeliveryOrder.cs`, `PickupOrder.cs` |
| P-02 — כפילות הקצאה | כל הזמנה נשמרת עם FK לעובד יחיד ברמת מסד הנתונים | טבלת `Orders`, FK `workerId` |
| P-03 — עובד לא יודע מה יש לו | `WatchOrdersPanel` מציג רק הזמנות של העובד המחובר | `Order.getOrders(workerId)` |
| P-04 — פרטים חסרים בשטח | `OrderDetailsPanel` מציג את כל פרטי ההזמנה: כתובת/סניף, מוצרים, כמויות | `OrderDetailsPanel.cs`, `OrderItem.cs` |
| P-05 — אין סימון הושלם | כפתור "סמן כהושלם" מופיע רק כשסטטוס = "פתוחה" — UC מסוג extend | `OrderDetailsPanel.cs`, `SP_UpdateOrderStatus` |
| P-06 — קטלוג לא עדכני | `Program.products` נטען בזמן אתחול; `ManageProductPanel` מאפשר עדכון בזמן אמת | `Product.cs`, `initProducts()` |
| P-07 — פיצול מידע עובדים | מסך `UpdateDeletePanel` — ניהול עובדים ממקום אחד; `Program.workers` | `Worker.cs`, `UpdateDeletePanel.cs` |
| P-08 — הרשאות לא נאכפות | `Title` enum + ניתוב ב-`LoginPanel` לפי תפקיד + בדיקת הרשאה בכל מסך ניהול | `Title.cs`, `LoginPanel.cs` |
| P-09 — חשיפת מידע לא מורשית | עובד רואה רק את ההזמנות שלו (`getOrders` מסונן); מנהל רואה הכל | `WatchOrdersPanel.cs`, `CRUDPanel.cs` |
| P-10 — אין תיעוד פעולות | כל Create/Update/Delete עובר דרך Stored Procedure — בסיס לאודיט עתידי | `NFR-16`, `NFR-15` |
| P-11 — אין דוחות | ארכיטקטורת in-memory (`Program.*`) מאפשרת חישוב דוחות מהיר ללא DB calls | `Program.cs`, `initLists()` |
| P-12 — לא ניתן להרחיב | מסד נתונים מרכזי (SQL Server) + ארכיטקטורה מבוססת-ישויות שניתן להוסיף אליה | `scripts/create_database.sql` |
